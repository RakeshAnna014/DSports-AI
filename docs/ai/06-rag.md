# 06 — RAG (knowledge base and product index)

```text
document → Apache Tika (+Tesseract OCR when the page has no text layer) → clean → heading-aware chunks (~450 tok, 60 overlap)
        → Vertex text-embedding-005 (768-d) → pgvector (HNSW, cosine) + PostgreSQL FTS
query   → metadata filter → keyword list + vector list → Reciprocal Rank Fusion → top K (5) → sanitised, fenced, cited → Gemini
```

All of it lives in `dsports_ai` (separate from the commerce database). Nothing in it is authoritative commerce data.

## Corpus (`ai-service/corpus/`, `manifest.yaml`)

Clearly labelled **SAMPLE** documents written for this project, not manufacturer documentation: return policy, refund policy,
shipping/tracking, FAQ, cricket-bat buying guide, running-shoe buying guide (the catalogue has no running shoe; it is a general
guide), cricket-bat care, an MRF product care sheet linked to `CR-BAT-MRF-001`, and a **scanned warranty card** (an image-only PDF
generated by `scripts/make_scanned_sample.py`, so only OCR can read it). The policy documents are written against the actual Java
behaviour (7-day window from delivery, partial quantities, REQUESTED/APPROVED/REJECTED, the refund lifecycle, the 30-minute
unpaid-order window). The E2E checks the stated 7 days against the live Returns eligibility response.

## Ingestion (`app/rag/ingest.py`, CLI `python -m app.cli ingest-corpus`)

* **Tika.** `PUT /rmeta/html` returns page-delimited HTML plus metadata. Headings/lists are converted back to light Markdown so the
  chunker can split on them.
* **OCR — what was measured, not assumed.** Tika 4.1 deliberately disables per-request parser configuration (HTTP 403 "Config
  endpoints are disabled") and ignores the old `X-Tika-PDFOcrStrategy` header, so a literal "extract without OCR, then retry with
  OCR" is not possible without weakening the server. Tika's own default OCRs **only pages that lack a text layer** and reports
  `pdf:chars-per-page` (digital text before OCR) and `pdf:ocr-page-count`. The service uses those: a PDF averaging fewer than
  `AI_OCR_MIN_CHARS_PER_PAGE` (50) digital characters per page is recorded as a scan, `ocr_used` is stored per document, and a scan
  that yields no text is rejected. Digital PDFs and Markdown never pay for OCR.
* **Chunking** (`rag/chunking.py`): split at headings and blank lines, oversized units by sentence then word, pack to ≤ 450 estimated
  tokens (chars/4), repeat the last ~60 tokens at the start of the next chunk. Chunks are per page, so page numbers are exact.
* **Metadata** per chunk: `product_id, category, sport, brand, document_type, source, version, language, page, chunk_index, section,
  content_hash` (+ document title).
* **Idempotency:** an unchanged document (bytes + metadata + embedding model + chunk parameters) is skipped; a changed document
  re-embeds only chunks whose embedding input changed. Embedding input = title + section + chunk text.
* **Embeddings:** batches of 16, dimension validated against `AI_EMBEDDING_DIM` before storage.

## Product index (`app/rag/products.py`, `index-products`)

One row per product: name, brand, category, sport, attributes, weight, composed search text, embedding, model, content hash.
**No price, stock, or customer data.** Unchanged products are not re-embedded; products that left the catalogue are removed.

## Model / dimension changes (`reindex`)

The stored `embedding_model|dimension` is compared at startup; a difference reports `reindex_required` in `/health/dependencies`.
`python -m app.cli reindex` resizes the vector columns if needed, re-embeds products and all stored chunk text, and only then records
the new model. Tested against real PostgreSQL (768 → 256).

## Retrieval (`app/rag/retrieval.py`)

Keyword list: `ts_rank_cd` over an OR-query of the question's words. Vector list: cosine distance (HNSW). Fusion: RRF, `k = 60`.
Filters (sport, category, brand, document type, product) apply inside both queries; general documents (no sport/category/product)
always qualify. Candidates: `AI_RETRIEVAL_CANDIDATES` (20), result `K = AI_TOP_K` (5). A hit with no keyword support and cosine
similarity below `AI_MIN_SIMILARITY` (0.5) is dropped: measured on the sample corpus, real answers scored ≥ 0.56 while
unrelated questions topped out at ≈ 0.38 with no keyword match, so those answer "not enough information" **without a model call**.
Reranking is not implemented (off by default; no evidence in the evaluation that it is needed). If the embedding model is
unavailable, retrieval degrades to keyword-only.

## Answering and citations

Retrieved text is untrusted data: instruction-like sentences are removed (`guard/untrusted.py`), the remainder is fenced in
`<untrusted_data>` blocks, and the system prompt says never to follow it. The model answers **only** from the numbered passages and
live DSports data and must cite `[n]`; `INSUFFICIENT_INFORMATION` produces the "not enough information" message; an answer without a
valid citation is not presented as grounded (the top passage is shown instead). Each citation returns
`{source, title, page, documentType, chunkId, snippet}`; the frontend shows them.

## Operations

```bash
uv run python -m app.cli status | index-products [--force] | ingest-corpus [--force] | reindex [--force]
uv run python -m app.cli ingest-file PATH --source S --type T | remove-document S
```
